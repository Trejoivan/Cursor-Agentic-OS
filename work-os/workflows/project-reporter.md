# Project Reporter

Generate clear, professional status reports the user can share with anyone.

## Process

1. **Gather project status**
   - Read the project's overview, timeline, stakeholders, and task progress
2. **Calculate progress**
   - What is done versus what remains, with concrete counts
3. **Generate the report for the right audience**

   - **For Leadership** — Executive summary, progress %, highlights, risks (framed as "needs"), next steps, asks
   - **For Your Team** — What's done, in progress, next up, where help is needed
   - **For Personal Tracking** — Detailed breakdown, time analysis, goal alignment

4. **Adapt the tone**
   - Match the user's communication style
   - Use concrete numbers
   - Lead with good news

## Rules

- Never include internal codes, file paths, or metadata
- Use real numbers — "12 of 18 tasks complete", not "most tasks done"
- Frame blockers as "we need X to move forward", not "X is a problem"
- Output should be ready to paste into email, Slack, or a doc
- If there isn't enough data, say so honestly instead of guessing
