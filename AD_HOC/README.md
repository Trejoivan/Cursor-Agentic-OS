# AD_HOC

`AD_HOC/` is a **hands-on workspace** for doing a single, concrete task (draft a meeting agenda, analyze options, prepare talking points, etc.).

Use `AD_HOC/workspace/` as the default scaffold/template for new tasks.

## How this fits with mini-bmad and BMAD

- **Do the work in `AD_HOC/`**: create a task folder, drop notes/artifacts, iterate quickly.
- **Summarize with `_mini_bmad/` when needed**:
  - If the ad-hoc work should be consolidated, checkpointed, or shared back to a major BMAD project, use a mini-bmad run as the **summary layer**.
  - Mini-bmad can represent a day/week/multi-week consolidation window (not just a single sitting).
- **Course-correct with `bmad-projects/` when decisions change scope**:
  - If the ad-hoc work results in official decisions (scope change, strategy shift, new constraints), use BMAD projects to update the “source of truth” plans/specs and re-align execution.

## Privacy model (recommended)

Keep ad-hoc task content private-by-default and publish only curated outputs to `Published/`.
